# Adaptive Block Routing with Cross-Block State Continuity in Hybrid Transformer–Mamba Language Models

**Parth Garg — VIT Vellore**

## Overview

This repository implements **Adaptive Block Routing (ABR)**, a hybrid architecture that dynamically routes fixed-size token blocks to either a Transformer (attention) or Mamba (SSM) expert at each layer. A key contribution is **Cross-Block State Continuity (CBSC)**, which propagates the recurrent hidden state across non-contiguous Mamba-routed blocks, allowing long-range sequential context to survive routing boundaries.

| Component | Description |
|---|---|
| **Block-level routing** | Groups tokens into blocks of size `k`; one routing decision per block |
| **Gumbel-Softmax router** | Discrete expert selection, fully differentiable via straight-through estimator |
| **Adaptive temperature** | Router entropy monitored during training; temperature adjusted to avoid collapse |
| **CBSC** | Last-token hidden vector of each Mamba block injected into the first token of the next Mamba block |
| **Weight tying** | Embedding and LM-head weights shared to reduce parameters |

## Installation

### 1. Create a Python 3.10 environment

```bash
python3.10 -m venv mamba_env
source mamba_env/bin/activate
```

On **Ubuntu/WSL2** if Python 3.10 is not installed:
```bash
sudo apt-get install python3.10 python3.10-venv python3.10-dev
```

### 2. Install PyTorch (CUDA build)

Go to [pytorch.org](https://pytorch.org/get-started/locally/) and select your CUDA version. Example for CUDA 12.1:

```bash
pip install torch==2.2.2 --index-url https://download.pytorch.org/whl/cu121
```

### 3. Install causal-conv1d and mamba-ssm (pre-built wheels)

> **Important:** Do NOT use `pip install mamba-ssm` directly — the PyPI source distribution has no CUDA files and will fail to build. Download the pre-built wheel for your exact CUDA/PyTorch/Python combination.

**Step 1** — determine your wheel suffix:
```python
import torch, sys
from packaging.version import parse
tv = parse(torch.__version__)
tc = parse(torch.version.cuda)
cuda_v = '122' if tc.major == 12 else '118'
torch_v = f'{tv.major}.{tv.minor}'
py_v = f'cp{sys.version_info.major}{sys.version_info.minor}'
abi = 'TRUE' if torch._C._GLIBCXX_USE_CXX11_ABI else 'FALSE'
print(f'Suffix: +cu{cuda_v}torch{torch_v}cxx11abi{abi}-{py_v}-{py_v}-linux_x86_64')
```

**Step 2** — download and install:
```bash
# Replace <suffix> with the output from Step 1
SUFFIX="+cu122torch2.2cxx11abiFALSE-cp310-cp310-linux_x86_64"

wget "https://github.com/Dao-AILab/causal-conv1d/releases/download/v1.4.0/causal_conv1d-1.4.0${SUFFIX}.whl"
pip install "causal_conv1d-1.4.0${SUFFIX}.whl"

wget "https://github.com/state-spaces/mamba/releases/download/v2.2.2/mamba_ssm-2.2.2${SUFFIX}.whl" -O "mamba_ssm-2.2.2${SUFFIX}.whl"
pip install "mamba_ssm-2.2.2${SUFFIX}.whl"
```

### 4. Install remaining dependencies

```bash
pip install numpy"<2" transformers==4.40.0 datasets ninja matplotlib packaging
```

### 5. Pre-cache the GPT-2 tokenizer (enables offline training)

```bash
python -c "
from transformers import GPT2TokenizerFast
tok = GPT2TokenizerFast.from_pretrained('gpt2')
tok.save_pretrained('~/gpt2_tokenizer')
print('Tokenizer saved.')
"
```

## Running the Full-Scale Experiments

All scripts live in `experiments/full_scale/`. Edit `config.py` to change model size, training steps, seeds, etc.

```bash
cd experiments/full_scale
```

### Train all ablation configs (6 configs × 3 seeds)

```bash
# Runs for ~25 hours on RTX 2050 (4GB). Run in background:
nohup python -u train_ablation.py > /tmp/train.log 2>&1 &
tail -f /tmp/train.log   # watch progress
```

Saves per-run JSON files and `results/ablation_aggregate.csv`.  
**Checkpoints** are saved every 2,000 steps — training auto-resumes if interrupted.

### Context-length benchmark

```bash
python bench_context.py
```

Saves `results/context_length_benchmark.csv` with PPL, tokens/sec, memory, latency, and GFLOPs for context lengths 128 → 1024.

### Router specialization analysis

```bash
python analyze_router.py
```

Saves plots in `results/router_analysis/`:
- `positional_bias.png` — does the router prefer Transformer or Mamba at specific positions?
- `routing_entropy_over_training.png` — router health over time
- `routing_seed_consistency.png` — agreement across different random seeds

### Generate paper figures

```bash
python plot_results.py
```

Saves IEEE-quality figures (300 DPI) to `results/figures/`.

## Key Design Decisions

**Why block-level routing instead of token-level?**
Token-level routing creates highly irregular memory access patterns that hurt GPU utilisation. Block-level routing keeps computation dense and hardware-friendly.

**Why Gumbel-Softmax with adaptive temperature?**
Fixed temperature leads to routing collapse (all tokens go to one expert). The adaptive schedule tracks routing entropy and nudges the temperature up when the router is too confident.

**Why CBSC?**
Without it, each Mamba block processes its tokens in isolation — the SSM's recurrent state resets at every block boundary. CBSC injects the last-token hidden vector of one Mamba block into the first token of the next, letting long-range sequential context survive routing.
